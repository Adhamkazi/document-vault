# Strict Pre-Execution Analysis Protocol

Before executing any file-editing tools, code writes, or destructive terminal commands, you MUST present a structured breakdown and wait for my confirmation.

Structure your response like this:

1. 🎯 **Objective & What We Did/Are Doing:**
   Summarize the specific task and what is being proposed.

2. 💡 **Why We Are Doing It:**
   Explain the technical reason or root cause driving this modification.

3. 📁 **Affected Files:**
   List all relative file paths that will be created, modified, or removed.

4. 🛠️ **Exact Changes Required:**
   Break down what will change in each file (functions added, variables modified, imports changed, etc.).

---

**CRUCIAL:** Stop after rendering this explanation and explicitly ask for confirmation before modifying any code.
